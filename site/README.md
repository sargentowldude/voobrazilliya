# ВообразилЛиЯ — детские праздники в Кемерово

Node.js/Express-сайт, собранный по `DESIGN (1).md` и рекламной структуре из `semantic-core-kemerovo.md`.

## Запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://localhost:3000`.

## Готовые страницы

- `/` — организация детских праздников;
- `/animatory/` — аниматоры;
- `/animatory-na-dom/` — аниматоры на дом;
- `/detskiy-den-rozhdeniya/` — день рождения под ключ;
- `/show/` — интерактивные шоу;
- `/spektakli/` — выездные спектакли.
- `/afisha/` — публичная афиша;
- `/admin/` — управление афишами.

Все страницы имеют отдельные Title, Description, H1 и рекламные формулировки.

## Заявки

Формы отправляют `POST /api/leads`. Сервер валидирует данные, сохраняет заявки построчно в `data/leads.jsonl` и отправляет их на настроенную почту по SMTP. Если настроены Telegram-переменные, после принятия SMTP-сервисом письма сервер дополнительно отправляет владельцу только нейтральный сигнал: «Новая заявка с сайта. Проверьте почту.» Имя, телефон, комментарий, время и ID заявки в Telegram не передаются. Заявка без заключённого договора автоматически удаляется через 90 дней; в `data/leads-deletion-log.jsonl` остаётся только техническая запись с ID и датами удаления. Оба файла исключены из Git.

Необходимо заменить тестовые телефон и email в `server.js`, разместить политику конфиденциальности и указать реальный `SITE_URL`.

## Афиши и админка

Афиши хранятся в `data/events.json`. В `/admin/` можно создавать и редактировать события, менять дату, описание, slug, цвет, изображение и статус публикации. Изображения сохраняются в `public/uploads/`.

Для локального запуска пароль — `tema-admin`. Перед публикацией обязательно задайте `ADMIN_PASSWORD` и `ADMIN_COOKIE_SECRET`.

Рекомендуемая будущая модель: `events`, `programs`, `characters`, `leads`, `users`, `media`. Для админки потребуются авторизация, роли, загрузка изображений, черновики и журнал изменений.

## Production

```bash
npm run check
npm start
```

Переменные окружения:

- `PORT` — порт приложения, по умолчанию `3000`;
- `SITE_URL` — публичный адрес для canonical-ссылок.
- `TRUST_PROXY=1` — включайте только за одним доверенным reverse proxy, чтобы лимиты запросов видели реальный IP посетителя.
- `ADMIN_USERNAME` — логин входа в админку;
- `ADMIN_PASSWORD` — пароль входа в админку;
- `ADMIN_COOKIE_SECRET` — секрет подписи административной сессии.
- `PERSONAL_DATA_EMAIL`, `PERSONAL_DATA_POSTAL_ADDRESS` — контакты оператора, публикуемые в политике.
- `YANDEX_METRIKA_ID` — ID счётчика; Метрика загружается только после отдельного согласия посетителя.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TO` — отправка заявок на почту.
- `TELEGRAM_LEADS_BOT_TOKEN`, `TELEGRAM_LEADS_CHAT_ID` — необязательное нейтральное уведомление владельцу после принятия письма SMTP-сервисом. Чтобы однократно получить ID личного чата после `/start`, задайте токен и при необходимости `TELEGRAM_LEADS_RECIPIENT_USERNAME`, затем выполните `npm run telegram:chat-id`; его вывод добавьте в `.env` как `TELEGRAM_LEADS_CHAT_ID`.
- `TELEGRAM_LEADS_API_BASE_URL` — адрес Telegram Bot API, по умолчанию `https://api.telegram.org`. Указывать иной адрес можно только для доверенного HTTPS-прокси: он получает токен бота и способен действовать от его имени.

Файл `.env` уже исключён из Git; безопасный шаблон лежит в `.env.example`.
